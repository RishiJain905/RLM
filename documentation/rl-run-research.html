Summary

Method

GRPO gained +0.20 held-out accuracy over base in 20 steps (~3 SE); RLSD's +0.09 wasn't significant. GRPO learned to make more sub-calls on hard tasks and fewer on easy ones. Every published RLM training run is GRPO-family.

Do: GRPO with the CISPO loss and no reward std scaling. RLSD is shelved; it can come back later as an ablation on top of GRPO.
Production settings

Hard-task episodes that ran out of the 20-call budget scored 0.25 vs 0.53, and sub-call use was still rising. GRPO only learns from groups with mixed results.

Do: sub-call budget 20 → ~30, a difficulty controller that raises the level as pass rate climbs, 32 episodes per step (8 tasks × 4 rollouts), restore the CISPO clip.
Do first

The audit found three gaps that make any result untrustworthy: no real sandbox, eval transcripts not logged, one seed per arm.

Do: sandbox (H2-H4), eval logging (H9) and a second 20-step GRPO seed (H12) before anything else spends budget.
Environment

A blind guess earns 0.31-0.53 reward today. The REPL can read the whole disk and reach the internet. Infra failures count against the model. Eval reuses training templates.

Do: calibrated partial credit, Docker sandbox, infra-error flags, hack zeroing, held-out generators, red-team. Each hole and its fix.
Datasets

Current tasks are ~8-10K tokens, inside the model's 262K window, so they don't test long context.

Do: generators with difficulty levels (OOLONG-style aggregation, code call-graph, needle-function) + Long Code Arena train. Public benchmarks are eval-only. Cyber was dropped by decision 7c (2026-10-11).
Cost and how long to train

Inference pays for every rollout and eval: yesterday's ~2,060 episodes cost $32.32, ~$0.016 each. Training GPU is ~$0.16 a step and not a constraint.

Fits: ~$218 of inference covers second seed, baselines, a ~$150 production ceiling (~80-180 steps), evals and a reserve. Stop by rule, not a step count.

Holes found, and the fix for each

Every hole in the current setup, the fix the production environment applies, and the check that proves it. A fix is done only when its check passes, and every check becomes a regression test. Cards marked Do first are Rishi's first priority (phases A and E of the plan); the rest land in environment v2 before the second-seed run.

H1

Partial credit pays for guessing

Problem

A guess from the line count earns 0.31-0.53 mean reward without reading anything (simulated). Not used yet in the 20-step run, but nothing stops it.

Fix

Keep partial credit (GRPO needs graded rewards to keep groups mixed) but calibrate it: exact = 1, near miss = 0.8 × max(0, 1 − err / e_blind), where e_blind is that task's blind-guess error, computed on the host. Exact accuracy is the headline.

Done when

A blind guesser scores no more than its exact-hit rate on every task family.

H2

The REPL can read the whole disk

Do first
Problem

Any path is readable, including .env (the W&B key) and past gold answers in .art/. One 20-step rollout wrote files to C:\tmp\.

Fix

Docker per episode: read-only filesystem except scratch, non-root, only context mounted. No repo, .art/, home or .env. Answers and graders stay on the host.

Done when

Tests opening .env, .art/, the repo, home and /proc, or writing outside scratch, all fail from inside.

H3

Tasks can be regenerated

Do first
Problem

Model code could import our generator and find the small, predictable seed (train 1000 + i, eval 99_999).

Fix

Comes with H2. Generators run on the host only, with random 64-bit seeds that never enter the sandbox. Eval seeds kept private.

Done when

Importing any project module from the sandbox fails; no seed is visible inside.

H4

The REPL can reach the internet

Do firstHow MiMo's models cheated
Problem

No network restriction on the subprocess.

Fix

Comes with H2. --network none; the only way out is the bridge over one socket, accepting only llm, llm_batch, submit.

Done when

pip install, curl and DNS fail; bridge calls still work.

H5

Infra failures count against the model

Cost MiMo 3 hours of Flash
Problem

A rate-limited sub-call returns [sub-call failed] as an answer. 4 RLSD episodes (0.6%) hit the 120 s timeout while sub-calls sat in the queue. A 30-call budget makes queue waits longer.

Fix

An infra_error flag per episode. Flagged episodes leave the group before advantages, are counted, and the step pauses above 1%. Queue time stops counting toward the cell timeout.

Done when

Forced 429s and a killed kernel yield flagged episodes, and none reach training.

H6

Sub-calls bypass the concurrency cap

Problem

Root calls share a cap of 8; the sub-call pool of 6 sits outside it, so ~14 can be in flight.

Fix

One shared limiter for every request, jittered backoff, exhausted retries become infra_error. Ask CoreWeave why 429 hits at 32.

Done when

A load test never exceeds the cap.

H7

Eval reuses the training templates

MiMo picked checkpoints on its reported benchmark
Problem

Train and eval come from the same ~40 sentence templates; only the seed differs.

Fix

Three tiers: selection set, held-out generators/sources/templates, public benchmarks. The last two run once.

Done when

No generator, template or source overlaps training; an n-gram overlap check passes.

H8

Tasks are too short to need an RLM

Problem

~8-10K tokens against a 262K window: the model could read them directly.

Fix

130K-1M-character contexts reached through the difficulty controller, plus a direct-reading baseline in every eval.

Done when

Top difficulty levels have median context above 130K characters; the direct-reading baseline is measured.

H9

Eval transcripts are not logged

Do first
Problem

evaluate_rlm saves only aggregates; the 300 eval episodes of the 20-step run were never audited.

Fix

Log every eval episode with its transcript, sub-calls, reward components and checkpoint (ART split="val" plus a local JSONL). The hack audit covers eval too.

Done when

A rerun eval writes one transcript per episode, and the audit script reads them.

H10

Env and harness use different names

Problem

Env: llm_query. Harness design: llm.

Fix

One shared bridge module (llm, llm_batch, submit, context) with pinned prompt text.

Done when

Both import the module; a test diffs their system prompts.

H11

Nothing detects or penalizes cheating

MiMo's hack zeroing kept hacks under 2%
Problem

No checks for turn-1 submits, answers copied from the prompt, or escape attempts.

Fix

Rule detectors that zero reward before the group mean, a Claude audit of sampled wins each step, and a red-team agent before production.

Done when

Detectors unit-tested, red-team finds no exploit, clean solve rate on the dashboard.

H12

One seed per arm

Do first
Problem

The 20-step result could partly be noise. GRPO vs base is ~3 SE (solid); GRPO vs RLSD is ~1.6 SE.

Fix

Repeat the 20-step GRPO run with a second seed on env v2 (same ticket tasks, ~$12 of inference). With no pilot, it is also the smoke test for the new env.

Done when

The second seed lands within ~1 SE of the first on held-out accuracy, or the gap is explained.

H13

Identical-reward groups teach nothing

Problem

In the 20-step GRPO arm, trainable groups fell from 7 of 8 to 3-6 of 8 as the model improved.

Fix

The difficulty controller keeps pass rates in the 20-70% band; all-equal groups are dropped from the update, not refilled (refills cost inference).

Done when

Most steps have at least 6 of 8 mixed groups, and the pass-rate histogram stays centred.

The RLSD-only hole from the earlier version (the teacher's hint could contain the answer) no longer applies: GRPO has no teacher.

It learned the RLM habit

It recursed where recursion pays and not elsewhere, and turned the same sub-call spend into more correct answers than RLSD.

It is what RLM training uses

The alphaXiv RLM run, the RLM paper's own RL run, MemAgent (DAPO) and Context-Folding (FoldGRPO) are all GRPO-family. No published RLM run used self-distillation.

It is simple and native

One scalar reward per rollout, exactly W&B serverless's interface. No teacher re-scoring, no logprob channel, no tokenizer round-trip (RLSD lost 19% of its teacher scoring to alignment failures).

No SFT needed

GRPO needs a non-zero starting pass rate. The 4B model in the alphaXiv run started at 0 and needed a cold start; Qwen3.8-27B starts around 0.5 on our tasks.

How GRPO maps onto an RLM episode

task ──► 4 rollouts from the same checkpoint
           each rollout = the root conversation:
           system + question + context metadata
           → code turn → truncated REPL output → code turn → … → submit()
           (sub-calls run inside the REPL; they are environment, not trained)
reward r_i per rollout ──► advantage A_i = r_i − mean(r of its group)
every root token in rollout i gets A_i; REPL output and sub-call text are masked
CISPO loss on those tokens ──► LoRA update

No std division

scale_rewards=False. Dividing by the group's std over-weights groups whose rewards barely differ (Dr. GRPO's difficulty bias). MiMo makes the same choice.

One advantage per episode

A good probe turn and a bad aggregation turn get the same credit: GRPO's known weakness on long episodes. Good enough in 20 steps; small process penalties only if a habit stalls.

Sub-calls are environment

Served by the frozen base model, not trained. Giving child calls the root's advantage (the alphaXiv next step) is a later follow-up.

Harder tasks as accuracy climbs

GRPO stops learning from a family once every rollout passes. A simple controller keeps the signal:

  1. Each generator has levels (context length, needles or attack slices, distractor density, question indirection). Level 1 is today's task size; the top is ~400K characters.
  2. After each step, per family, take the rolling pass rate over the last 3 steps. Above ~70%: up a level. Below ~20%: down. Otherwise stay.
  3. All-equal groups within a level are dropped from the update.
  4. Log the level per family; evaluate on the fixed selection set so curves stay comparable.

The RLM paper's recipe in automatic form (trained at 32-64K, evaluated at 512K-1M), and MiMo's easy-prompt pruning by another route.

How their models cheated

Early coding runs passed tests without solving the task by fetching the fix from outside:

  • pip install a newer release and read the fixed source
  • curl the fixed file from a raw GitHub URL
  • git clone a later checkout
  • read the fixed issue in the tracker
  • pip index versions to find the fixed release

Also: drift to code that passes but is bad. The cyber dataset was dropped after "some bad patterns" in rollout logs, and cyber grading moved from an LLM judge to a deterministic sanitizer-report match.

How they fought it

  1. Environment prep: no logs or caches, git cut to the base commit, no network.
  2. Hack agent probed every env until it found no exploit.
  3. Hack zeroing before the group mean: (1,1,1,0) with one hack → (1,1,0,0); advantages (.25,.25,.25,−.75) → (.5,.5,−.5,−.5). Zeroing after the mean would leave the hack with a positive advantage. Confirmed hacks <2%.
  4. Quality ranking among passing attempts.
Incidents: an infra error went undetected for ~3 hours and sandbox failures were scored 0 (Flash rolled back to step 15). Some subsets reached 70-80% of prompts at 100% pass, killing the GRPO signal.

The RL environment

Reward: calibrated partial credit

The prompt states the line count and the generator fixes the class mix, so round(n_lines × share) earns partial credit without reading a ticket. GRPO needs graded rewards to keep groups mixed, so instead of dropping partial credit we scale it by the blind guess's error. Simulated mean reward of a blind guess:

tickets_all, today
0.53
tickets_all, calibrated
0.06
tickets_customer, today
0.31
tickets_customer, calibrated
0.11

With calibration a blind guess earns only its lucky exact hits, while an answer closer than the guess still earns credit.

Reward rules

  • Exact: 1 (lists by set-F1)
  • Near miss: 0.8 × max(0, 1 − err / e_blind)
  • No submit: 0; no length penalty at first
  • Hack detected: 0, before the group mean
  • Infra error: excluded from the group, not scored
  • Process penalties only if a habit stalls

Hack detectors (zero reward before the mean)

  • turn-1 submit, or no read of context

Red-team before production

A Claude agent tries guessing, file reads, seed recovery, network, crashing the grader and malformed submit values. Fix, add a test, repeat until it fails. No credit needed.

Infra errors are not the model's fault

Flag infra_error, drop flagged episodes before advantages, alert above ~1%, and stop counting sub-call queue time toward the cell timeout. Matters more with a 30-call budget.

Concurrency and cost

What "8" means

How many requests are in flight at once. A production step is roughly 32 episodes × ~10 root turns plus up to ~30 sub-calls each: hundreds to a couple of thousand requests.

In the 20-step run a 32-episode step took 150-390 s at 8-way. One at a time, at 10-30 s per 27B root turn, it would be an hour or more per step.

Cost is per token ($0.40/M input, $0.15/M cached, $3.00/M output for Qwen3.8-27B). Same price at 1 or 8. Training GPU time is billed separately, against the $1,000 training credit.

Two things to fix

  • Sub-calls bypass the cap (H6). The bridge has its own pool of 6, so ~14 run at once. One limiter for everything, jittered backoff, exhausted retries become infra errors. Try 16 once support answers.
  • Our 429 at 32 is odd. CoreWeave documents 2,000 concurrent requests per user and 6,000 per project. Email support with request ids, and confirm Qwen3.8-27B training stays supported.

How long to train, and when to stop

No fixed step count: 60 steps could stop while the model is still improving, or keep paying after it has stopped. Production runs against its ~$150 inference ceiling and stops by rule.

Every 10 steps

Evaluate on the fixed 64-task selection set (~$2.50) and a ~100-prompt capability check (cents). Save the checkpoint; track the best so far.

Keep going while the selection set set a new best in one of the last 3 evals, or a family moved up a level in the last 30 steps.

Stop early, keep the best checkpoint

  1. Plateau: no new best for 3 evals (30 steps) and no level-up.
  2. Overfitting: train reward up, selection set down, 2 evals running.
  3. Frying: capability check down >2 points, or a collapse that returns after one rollback with lower LR.
  4. Saturation: every family at its top level above ~70% pass. Next step is harder data, not more steps.
  5. Hacking that needs an env change: pause, fix, resume.

If it may need more

At the ceiling, if both of the last 2 evals were new bests, spend the ~$25 reserve (about 15-25 more steps), then check with Rishi.

Stopping isn't final: ART keeps the LoRA checkpoints, so a stopped run can resume from its latest or best checkpoint when more inference credit appears.
